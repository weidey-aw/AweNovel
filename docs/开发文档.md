# AweNovel 开发文档

> 面向参与开发的同学，说明本地怎么跑起来、代码怎么组织、数据怎么设计，以及关键业务的约定。
> 部署与运维请看 [`部署文档.md`](部署文档.md)。

## 1. 技术栈

| 层 | 选型 |
|---|---|
| 后端 | Java 17、Spring Boot 3.3.7、Spring Security（JWT + RBAC）、MyBatis-Plus 3.5.7、MySQL、Redis、Druid、Flowable 7.1（内容审核工作流） |
| 前端 | Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router（pnpm workspace monorepo） |
| AI | DeepSeek（OpenAI 兼容接口，流式对话） |
| 看板娘 | Live2D（pixi.js + pixi-live2d-display），无模型时降级为静态形象 |

## 2. 仓库结构

```
AweNovel/
├── pom.xml                   # 后端 Maven 父工程
├── weidey-admin/             # 启动入口（AweNovelApplication）+ 管理端控制器
├── weidey-framework/         # 安全、缓存、MyBatis、资源映射等框架配置
├── weidey-system/            # 系统管理（用户/角色/菜单/字典/参数/公告/日志）
├── weidey-common/            # 通用工具、基础实体、统一响应
├── weidey-AweNovel/          # 社区业务模块
│   └── com.weidey
│       ├── community         # 游戏、会社、标签、文章、资源、评论、评分、积分、收藏、消息、反馈、审核
│       └── ai                # 看板娘 AI 对话
├── web-ui/                   # 前端 monorepo
│   ├── web/                  # 用户端（前台）
│   ├── admin/                # 管理端（后台）
│   └── shared/               # 共享类型、接口封装、Markdown 与主题工具
└── docs/                     # 文档（本地维护）
```

> 数据库脚本、部署资料、真实密钥、构建产物都不在仓库内，由维护者本地保管。

## 3. 本地开发环境

### 3.1 准备

- JDK 17+、Maven 3.9+
- Node 20+、pnpm 8+
- MySQL（库名 `awe_novel`，字符集 `utf8mb4`）、Redis
- 数据库初始化/升级脚本：向维护者获取后在本地执行

后端本地私有配置放在 `weidey-admin/src/main/resources/application-local.yml`（已 gitignore，可参考 `application-local.example.yml`），至少包含数据库账号密码；开发环境默认加载 `dev,local` 两个 profile。

### 3.2 启动后端

```bash
mvn clean package -DskipTests
java -jar weidey-admin/target/weidey-admin.jar
```

或直接在 IDE 中运行 `com.weidey.AweNovelApplication`。默认端口 `9090`，接口根路径 `/`。

### 3.3 启动前端

```bash
cd web-ui
pnpm install
pnpm dev:web      # 用户端  http://localhost:5173
pnpm dev:admin    # 管理端  http://localhost:5174
```

前端开发服务器默认把 `/api` 代理到 `http://localhost:9090`（并去掉 `/api` 前缀）。后端不在默认端口时：

```bash
# PowerShell
$env:VITE_API_TARGET='http://127.0.0.1:9091'
pnpm dev:web
```

### 3.4 测试账号

初始化脚本内置 `admin / admin123`（超级管理员）。普通用户可自行注册，或在后台新建。

## 4. 前端约定

- **请求前缀**：所有接口调用统一走 `/api/xxx`，开发态由 Vite 代理剥离，生产由 Nginx 剥离（见部署文档）。
- **共享包**：类型定义、接口函数、Markdown 渲染、主题工具都放在 `@gal/shared`，前台/后台复用。
- **管理端路由**：由后端 `/getRouters` 下发，前端动态注册；静态页（登录、仪表盘、错误页、游戏整页编辑器）写在前端路由里。
- **管理端部署路径**：路由使用 `import.meta.env.BASE_URL`，构建时可通过 `ADMIN_BASE=/admin/` 指定子路径。
- **主题**：`shared/theme.ts` 负责读写主题；两套色板分别在前台/后台的 `styles/theme.css` 中维护，通过 `<html data-theme="...">` 生效，新增色板只需加一组变量。
- **代码块**：Markdown 渲染基于 highlight.js，前台/后台样式变量在各自 `styles/index.css`。
- **看板娘**：`components/live2d.ts` 负责加载模型与动作；模型目录 `web/src/locales/live2d/` 已 gitignore，缺失时自动显示静态形象。

## 5. 后端约定

### 5.1 分层

`controller`（参数校验、权限）→ `service`（业务逻辑）→ `mapper`（数据访问）→ `domain`（实体），公共响应使用 `AjaxResult`（对象）与 `TableDataInfo`（分页）。

### 5.2 权限

- 接口权限注解 `@PreAuthorize("@ss.hasPermi('module:entity:action')")`；
- 菜单与按钮权限存于 `sys_menu`，通过角色分配；
- 新增权限需要在数据库菜单表中增加记录，并给对应角色授权；
- 前端按钮显隐使用登录信息里的权限集合。

### 5.3 分页与筛选

统一 `pageNum` / `pageSize`；时间区间参数放在 `params[beginTime]` / `params[endTime]`；列表接口返回 `{ code, msg, total, rows }`。

### 5.4 状态约定

| 对象 | 状态 |
|---|---|
| 游戏 | `0` 下架 / `1` 已发布 / `2` 待审核 / `3` 驳回 / `4` 草稿 |
| 文章、资源 | `0` 待审核 / `1` 通过 / `2` 拒绝 |
| 评论、反馈 | 评论 `1` 正常 / `0` 隐藏；反馈 `0` 未读 / `1` 已读 |

### 5.5 文件与上传

上传目录由 `awenovel.profile` 指定，通过 `/profile/**` 对外访问；上传接口返回相对路径，前端用统一工具拼接资源地址。

## 6. 数据设计

数据库分三类表：

| 分类 | 主要表 |
|---|---|
| 系统 | `sys_user`、`sys_role`、`sys_menu`、`sys_role_menu`、`sys_user_role`、`sys_dict_type`、`sys_dict_data`、`sys_config`、`sys_notice`、`sys_oper_log`、`sys_logininfor` |
| 社区 | `gal_game`、`gal_brand`、`gal_tag`、`gal_game_tag`、`gal_article`、`gal_resource`、`gal_resource_source`、`gal_official_resource`、`gal_comment`、`gal_rating`、`gal_user_favorite`、`gal_user_follow`、`gal_user_like`、`gal_user_profile`、`gal_point_log`、`gal_sign_record`、`gal_message`、`gal_resource_feedback`、`gal_level_config` |
| 流程 | Flowable 的 `ACT_*` 表（首次启动自动创建） |

几个关键关系：

- 一个游戏对应多个资源；一个资源对应多个「资源来源」（链接、提取码、解压码）；
- 正版资源按游戏配置，不关联用户；
- 评论、收藏、点赞、评分都按 `targetType + targetId` 关联目标对象（`G` 游戏 / `A` 文章 / `R` 资源）；
- 资源反馈会写入站内消息，消息带业务来源（`bizType` / `bizId`）。

> 建表与初始数据脚本由维护者单独维护，新增字段/表时同步提供增量脚本，避免各环境结构不一致。

## 7. 关键业务说明

### 7.1 内容审核

文章与资源提交后进入审核流程（Flowable），后台「内容审核」中通过或拒绝，结果写回业务状态；审核中的内容不能重复提交，编辑也会被限制。

### 7.2 积分与等级

注册不赠送积分；每日签到获得积分与经验；下载资源与 AI 聊天消耗积分；经验决定等级（0~6 级）。积分变动都会写入流水，便于审计。

### 7.3 资源与下载

资源由用户发布或管理员维护；一个资源可配置多条来源，下载时校验审核状态与积分，返回全部来源信息。资源失效等问题通过「反馈」通知上传者。

### 7.4 收藏与消息

收藏为切换式接口，列表会补全标题、封面与跳转地址；消息区分未读/已读，支持标记已读，反馈消息会显示发送人。

### 7.5 AI 看板娘

后端代理 DeepSeek 流式接口，支持携带多轮上下文；每次成功对话扣 1 积分，失败自动退还；前端失败时降级为非流式接口。人设与模型可通过环境变量调整。

### 7.6 审核与运营的边界

前台只展示审核通过的内容；下架操作用于已发布内容临时隐藏；删除操作需谨慎，部分删除会级联清理关联数据（如文章评论、资源来源）。

## 8. 接口一览

| 分组 | 前缀 | 说明 |
|---|---|---|
| 认证 | `/login`、`/register`、`/captchaImage` | 登录、注册、验证码 |
| 系统管理 | `/system/**` | 用户、角色、菜单、字典、参数、公告 |
| 系统监控 | `/monitor/**` | 在线用户、定时任务、服务、缓存、日志 |
| 游戏 | `/community/game/**` | 列表、详情、发布、撤回、下架、管理端 CRUD |
| 内容 | `/community/article/**`、`/community/resource/**`、`/community/comment/**`、`/community/rating/**` | 文章、资源、评论、评分 |
| 用户中心 | `/community/user/**` | 资料、积分、签到、消息、收藏、关注 |
| 审核 | `/community/review/**` | 待办、通过、拒绝 |
| AI | `/ai/**` | 流式对话、非流式兜底 |

约定：除登录/注册/公开列表外，均需携带 `Authorization: Bearer <token>`；令牌默认 7 天有效并随请求滑动续期。

> 详细字段与示例以维护者本地保存的接口文档为准；新增/修改接口时请同步更新。

## 9. 构建与发布

```bash
# 后端
mvn clean package -DskipTests

# 前端
cd web-ui
pnpm typecheck
pnpm build:web
ADMIN_BASE=/admin/ pnpm build:admin
```

发布时按部署文档替换 jar 与静态文件；如果做单机演示包，需要把前端构建产物随 jar 一起分发，并注意不要把本地密钥打进包内。

## 10. 代码规范与协作

- 分支：日常开发在 `dev`，稳定后合并到 `main`；
- 提交信息遵循 [`docs/dev/AI提交规范.md`](dev/AI提交规范.md)：`type: 简短中文说明`；
- 本地私密文件（`application-local.yml`、密钥、证书）必须保持 gitignore；
- 新增配置优先使用环境变量或本地配置文件，禁止在将apikey上传仓库！；
- 数据库变更必须提供可重复执行的增量脚本，并说明升级顺序；
- 前端提交前跑 `pnpm typecheck`，后端提交前确保 `mvn package` 通过。

## 11. 常见开发问题

| 问题 | 处理 |
|---|---|
| 前端请求 401 | 检查是否登录、令牌是否过期；确认请求走了 `/api` 前缀 |
| 刷新页面 404 | 开发态检查 Vite 代理是否误代理了前端路由；生产检查 Nginx 的 history 回退 |
| 后台资源 404 / 白屏 | 管理端构建路径与部署路径不一致（`/admin/`） |
| 上传图片不显示 | 上传目录不可写，或 `/profile` 未正确代理 |
| 端口冲突 | 后端 9090、前台 5173、后台 5174，可改配置或启动参数 |
| 中文乱码 | 数据库与连接字符集使用 `utf8mb4`；Windows 终端注意编码 |
| 看板娘没有立绘 | 本地缺少 Live2D 模型目录，属正常降级；需要时向维护者获取模型资源 |
| 审核流程异常 | 检查 Flowable 表是否创建、当前账号是否有审核权限与候选组 |
