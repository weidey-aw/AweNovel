# AweNovel 部署文档

> 面向部署与运维人员。文档只描述「怎么把项目跑起来、怎么维护」；开发相关内容见 [`开发文档.md`](开发文档.md)。

## 1. 部署方式

AweNovel 是前后端分离的站点，常见有三种运行方式：

| 方式 | 适用场景 | 说明 |
|---|---|---|
| 本地开发模式 | 开发、调试 | 后端 + 前台开发服务器 + 后台开发服务器，改代码即时生效 |
| 生产部署（推荐） | 正式对外 | 后端 jar 常驻，前端构建成静态文件，由 Nginx 统一对外 |
| 单机演示 | 内网演示、验收 | 前后台静态文件与后端放在同一台机器，一个端口访问（维护者可提供现成测试包） |

下面按「数据库 → 后端 → 前端」的顺序说明。生产部署建议使用 Linux 服务器。

## 2. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11、Linux | 生产推荐 Linux |
| JDK | 17 及以上 | 后端运行环境 |
| MySQL | 5.7 / 8.x | 主数据库 |
| Redis | 5 及以上 | 登录状态、验证码、缓存 |
| Node.js + pnpm | Node 20+ / pnpm 8+ | **仅构建前端时需要**，运行时不需要 |
| Nginx | 任意稳定版 | 生产环境反向代理与静态资源托管 |

> 数据库初始化脚本、增量升级脚本与部署资料由维护者单独提供，**不随仓库发布**。

## 3. 数据库准备

1. 安装并启动 MySQL，创建业务库（默认库名 `awe_novel`，字符集 `utf8mb4`）。
2. 导入维护者提供的初始化脚本（通常命名为 `awe_novel.sql`，包含建表与初始数据）：

```bash
mysql -uroot -p --default-character-set=utf8mb4 < awe_novel.sql
```

3. 如果从旧版本升级，按维护者提供的增量脚本顺序执行（脚本可重复执行，执行前请先备份）。
4. 审核流程所需的流程表（`ACT_*`）由应用首次启动时自动创建，数据库账号需要有建表权限。

> 初始化脚本会创建默认管理员 `admin / admin123`，部署完成后请立即修改密码。

## 4. 后端部署

### 4.1 构建

```bash
mvn clean package -DskipTests
```

产物：`weidey-admin/target/weidey-admin.jar`。

### 4.2 配置

敏感配置全部通过环境变量注入，仓库中不含真实密钥：

| 环境变量 | 必填 | 说明 |
|---|---|---|
| `DB_URL` | 否 | 数据库地址 |
| `DB_USERNAME` / `DB_PASSWORD` | 是 | 数据库账号密码 |
| `TOKEN_SECRET` | 是 | 登录令牌签名密钥，至少 32 字节，生产必须替换 |
| `MAIL_HOST` / `MAIL_USERNAME` / `MAIL_PASSWORD` | 否 | 邮箱服务（注册、找回密码验证码） |
| `DEEPSEEK_API_KEY` | 否 | 看板娘 AI 的 DeepSeek Key，不配置则聊天不可用 |
| `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` / `DEEPSEEK_PERSONA` | 否 | AI 接口地址、模型、人设，一般无需修改 |
| `DRUID_USERNAME` / `DRUID_PASSWORD` | 否 | 数据库监控台账号，生产建议修改或关闭外网访问 |

其他需要按现场调整的配置（在配置文件中修改）：

- **服务端口**：默认 `9090`（`server.port`）；
- **上传目录**：`awenovel.profile`，Linux 示例 `/home/awenovel/uploadPath`，Windows 示例 `D:/AweNovel/uploadPath`；
- **Redis**：默认 本地、无密码；如有密码在配置中设置 `spring.data.redis.password`。

> 也可以使用不入库的 `application-local.yml` 在服务器本地覆盖配置；该文件切勿提交到仓库。

### 4.3 启动

```bash
java -jar weidey-admin.jar
```

生产环境建议注册为系统服务（以 systemd 为例）：

```ini
[Unit]
Description=AweNovel
After=network.target mysql.service redis.service

[Service]
User=awenovel
WorkingDirectory=/home/awenovel
EnvironmentFile=/home/awenovel/.env
ExecStart=/usr/bin/java -Xms512m -Xmx1024m -jar /home/awenovel/weidey-admin.jar
Restart=always

[Install]
WantedBy=multi-user.target
```

`/home/awenovel/.env` 中放置 `DB_PASSWORD`、`TOKEN_SECRET` 等环境变量；上传目录需提前创建并授予运行用户写权限。

## 5. 前端部署

前端包含两个站点：

- **用户端**（前台）：默认部署在根路径 `/`；
- **管理端**（后台）：建议部署在 `/admin/` 子路径（也可使用独立域名）。

### 5.1 构建

```bash
cd web-ui
pnpm install
pnpm build:web                          # 产物：web/dist
ADMIN_BASE=/admin/ pnpm build:admin     # 产物：admin/dist（部署到 /admin/ 时必须带该参数）
```

> Windows PowerShell 中设置环境变量：`$env:ADMIN_BASE='/admin/'; pnpm build:admin`。

部署时把 `web/dist` 的内容放到站点根目录（如 `/var/www/awenovel/web/`），
把 `admin/dist` 的内容放到该目录下的 `admin/` 子目录，即可对应下面的 Nginx 配置。

### 5.2 Nginx 配置参考

```nginx
server {
    listen 80;
    server_name example.com;

    # 目录约定：前台文件放 web/，管理端文件放 web/admin/
    root /var/www/awenovel/web;
    index index.html;

    # 前台（history 路由回退）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 管理后台（与前台同根目录下的 admin/ 子目录）
    location /admin/ {
        try_files $uri $uri/ /admin/index.html;
    }

    # 接口：去掉 /api 前缀后转发给后端
    location /api/ {
        proxy_pass http://127.0.0.1:9090/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # AI 聊天使用流式输出，必须关闭缓冲
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }

    # 上传文件（头像、封面、截图等）
    location /profile/ {
        proxy_pass http://127.0.0.1:9090/profile/;
    }
}
```

要点：

- 前端所有请求都带 `/api` 前缀，Nginx 转发时**去掉该前缀**（`proxy_pass` 末尾的 `/`）；
- 管理端构建参数与部署路径必须一致（`/admin/`），否则会出现白屏或资源 404；
- AI 对话接口是流式响应，必须关闭代理缓冲，否则会「很久才出字」。

### 5.3 客户端缓存建议

- `index.html` 不缓存；
- `/assets/` 下的带哈希静态文件可长期缓存。

## 6. 单机演示（可选）

如果只想在一台机器上快速演示，可以让后端同时托管前端静态页面：把构建好的前台文件放在根路径、管理端放在 `/admin/` 子目录，再通过反向代理或应用自身提供页面，即可用一个端口访问前后台。

维护者通常会直接提供一个已打包好的 Windows 测试包，解压后运行启动脚本即可，无需自己构建。测试包使用独立端口（默认 `8088`），首次使用需先初始化数据库。

## 7. 升级流程

1. 备份数据库与上传目录；
2. 拉取新版本代码，按需执行维护者提供的增量 SQL；
3. 重新构建后端 jar 与前端静态文件；
4. 替换产物并重启服务；
5. 打开前台与后台各页面做一次冒烟检查（首页、游戏详情、登录、后台仪表盘）。

## 8. 备份与恢复

| 内容 | 建议 |
|---|---|
| 数据库 | 每日 `mysqldump` 全量备份，保留 7~30 天 |
| 上传目录 | 与数据库同周期备份（用户头像、封面、截图、文章图片） |
| 配置文件 | 单独保存环境变量与本地配置文件，切勿入库 |
| 恢复 | 先恢复数据库，再把上传目录放回原路径，最后启动服务 |

## 9. 常见问题

| 现象 | 排查方向 |
|---|---|
| 启动报数据库连接失败 | MySQL 是否启动、`DB_URL` 与账号密码是否正确、库是否存在 |
| 启动报 Redis 连接失败 | Redis 是否启动、端口与密码是否正确 |
| 后台登录提示验证码错误 | Redis 是否正常、服务器时间是否准确 |
| 上传图片后 404 | 上传目录是否存在且可写；`/profile` 是否正确代理到后端 |
| 后台页面白屏 | 管理端构建参数与部署路径是否一致（`/admin/`） |
| 刷新后台页面 404 | Nginx 是否配置了 history 回退（`try_files ... /admin/index.html`） |
| 看板娘不回复 | 是否配置 `DEEPSEEK_API_KEY`、服务器能否访问 DeepSeek、用户积分是否足够 |
| AI 回复很慢或一次性弹出 | 反向代理是否关闭了缓冲（`proxy_buffering off`） |
| 后台提示无权限 | 账号角色是否分配了对应菜单权限 |
| 中文乱码 | 数据库与连接字符集是否为 `utf8mb4` |

## 10. 安全建议

- 首次部署后立即修改 `admin` 默认密码；
- 必须替换 `TOKEN_SECRET`，不要使用默认值；
- 所有密钥通过环境变量或本地配置文件注入，**严禁提交到仓库**；
- 生产环境启用 HTTPS，并限制数据库监控台（Druid）仅内网访问；
- 数据库使用独立账号，只授予业务库所需权限；
- 定期轮换 DeepSeek Key、邮箱授权码与数据库密码。
